OCR → Inventory

A typed backend for turning invoice OCR into structured inventory.

Upload raw OCR text. Extract line items. Normalize supplier names against a canonical catalog using MiniLM embeddings + pgvector. Update the inventory ledger.

Architecture

pipeline

Stages

01
Ingest

OCR text posted as JSON, plain text, or CSV. No image parsing — the OCR layer sits upstream.

02
API

Express with JWT auth. Creates the invoice row, writes the file to storage, enqueues a job.

03
Queue

BullMQ on Redis. Inline fallback when Redis is absent. Idempotent per invoice id.

04
Extract

Worker pulls the file, splits line items, calls the normalizer with raw name, qty, unit.

05
Normalize

Preprocess → MiniLM embed (384-d) → pgvector k-NN → weighted hybrid score → confidence router.

06
Persist

Invoice, line items, routing decisions, score breakdowns stored in PostgreSQL.

07
Inventory

Auto-committed matches update the ledger immediately. Review items are queued for human check.

08
Stream

Server-sent events push status transitions to the client for live monitoring.
